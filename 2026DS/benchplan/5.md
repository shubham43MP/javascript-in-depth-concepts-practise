| Feature                           | `var`                          | `let` | `const` |
| --------------------------------- | ------------------------------ | ----- | ------- |
| Scope                             | Function/global                | Block | Block   |
| Hoisted                           | Yes                            | Yes   | Yes     |
| Initialized during creation       | `undefined`                    | No    | No      |
| TDZ                               | No                             | Yes   | Yes     |
| Redeclaration same scope          | ✅                              | ❌     | ❌       |
| Reassignment                      | ✅                              | ✅     | ❌       |
| Global becomes `window` property* | Usually yes in classic scripts | No    | No      |


```
var, let, and const all create bindings and are all hoisted, but their environment and initialization semantics differ. var is function-scoped and initialized to undefined when its environment is instantiated, which is why it can be accessed before the declaration. let and const are lexical, block-scoped bindings and remain uninitialized until their declaration is evaluated, creating the Temporal Dead Zone. const additionally prevents reassignment of the binding, not mutation of the referenced object. Another important distinction is that lexical declarations in for loops can create per-iteration bindings, which changes closure behavior compared with var. In production code I default to const, use let when reassignment expresses real state transition, and generally avoid var.
```
